# Putting Echo on your website

Squarespace can't run Python, so the app runs on [Render](https://render.com) with its database on [Neon](https://neon.com). You then point a subdomain of your Squarespace site at it, for example `echo.yoursite.com`, and link to it from your site.

Both services have free plans. You need a GitHub account, and (as before) Spotify Premium on the account that owns the Spotify app.

Throughout this guide, replace `echo.yoursite.com` with the subdomain you choose.

## 1. Put the code on GitHub

Render deploys from a Git repository. Create an **empty** repository on GitHub (no README), then in the project folder:

```bash
git remote add origin https://github.com/<your-username>/echo.git
git push -u origin main
```

## 2. Create the database on Neon

1. Sign up at neon.com and create a project. Pick the region closest to where you'll run the app.
2. Copy the **connection string**. It starts with `postgresql://`. Keep it private; it contains the database password.

## 3. Create the app on Render

1. Sign up at render.com and connect your GitHub account.
2. Choose **New → Blueprint** and select your `echo` repository. Render reads `render.yaml` and asks for four values:
   - `DATABASE_URL`: the Neon connection string from step 2.
   - `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET`: from your Spotify app.
   - `SPOTIFY_REDIRECT_URI`: `https://echo.yoursite.com/callback`
3. Click **Apply** and wait for the first deploy to finish.
4. Open the `onrender.com` address Render shows for the service and click **Try the demo**. If you see matches, the app and database are working.

The secret keys are generated by Render. On first start the app creates 150 demo listeners for the demo button.

## 4. Point your Squarespace subdomain at Render

1. In Render, open the service, go to **Settings → Custom Domains**, and add `echo.yoursite.com`. Note the `onrender.com` address it tells you to point to.
2. In Squarespace, go to **Domains**, pick your domain, open **DNS**, and click **Add record**:
   - **Host:** `echo`
   - **Type:** `CNAME`
   - **Data:** the `onrender.com` address from step 1
3. Save, go back to Render, and click **Verify**. DNS changes can take a few minutes to an hour. Render issues the HTTPS certificate automatically once verification succeeds.

If your domain is registered somewhere else (GoDaddy, Namecheap and so on) and only connected to Squarespace, add the CNAME record at that registrar instead.

## 5. Update Spotify

In the Spotify developer dashboard, open your app's settings and add this redirect URI:

```
https://echo.yoursite.com/callback
```

Keep the `http://127.0.0.1:8000/callback` one too, so running locally still works. Accounts that should be able to log in still need to be added under **User Management** (5 maximum).

## 6. Link to it from your site

In the Squarespace editor, add a navigation link or a button pointing to `https://echo.yoursite.com`. For a portfolio, `https://echo.yoursite.com/demo` drops visitors straight into the demo.

## Things to know

- **Cold starts.** On Render's free plan the app sleeps after 15 minutes without visitors, and the next visit takes about a minute to wake it. If you're sending the link to recruiters, a paid instance keeps it awake.
- **Updates.** Every `git push` to `main` redeploys automatically.
- **Refreshing data.** Real users' artists refresh whenever they log in or click "Refresh my artists". A scheduled refresh (`python -m echo refresh`) would need a cron job, which Render doesn't offer on the free plan.
- **Without Neon.** If you leave `DATABASE_URL` empty, the app uses SQLite on Render's temporary disk. The demo still works, because demo listeners are recreated at startup, but real users' data disappears on each restart.
